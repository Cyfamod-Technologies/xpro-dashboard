# Dashboard ↔ API coverage map

**Audit date:** 31 October 2026. **Scope:** the current Xpro dashboard routes and controls, compared with `xpro-server` controllers and the target flows in `xpro-doc/specs/01–06`. This is a source-code audit; it does not certify that a request works against a running database, Redis, Paystack, SMS, email, or object storage.

## How to read this inventory

- **✅ Wired:** the live dashboard has a visible control or view, a client call, and a matching server route. Read and write behavior still needs end-to-end verification.
- **🟡 Partial:** a route and some client code exist, but the page uses demo state, a control is absent, or a significant part of the flow is missing.
- **⚠️ Contract gap:** the visible live flow calls a path or shape that does not match the server.
- **⬜ Needed:** required by the page or target flow, with no working live dashboard control. The server may already expose the route.

Each table row is one user-facing capability. Related buttons that submit the same endpoint with a different decision are grouped in one row. **Code coverage = ✅ rows ÷ all rows**; partial and contract-gap rows score zero. The figure measures wiring, not production readiness. `:id`, `:aid`, `:qid`, `:sid`, `:uid`, `:iid` and `:eid` are resource IDs. For request commands, `If-Match` carries the request version and `Idempotency-Key` is supplied by the shared command helper; uploads use create → presigned `PUT` → complete. Amounts are integer kobo, times are UTC on the wire and displayed in WAT.

**Source map:** [page dispatch](../../resources/ts/features/workspace/SectionView.vue), [workspace routes](../../resources/ts/features/workspace/config.ts), [request adapter](../../resources/ts/services/requests-api.ts), [provider adapter](../../resources/ts/services/providers-api.ts), [auth adapter](../../resources/ts/services/xpro-api.ts), [staff adapter](../../resources/ts/services/staff-api.ts), [catalog adapter](../../resources/ts/services/catalog-api.ts). Server controllers live in `xpro-server/src/{auth,requests,providers,payments,staff,platform,approvals,notifications}`. The authoritative target is `xpro-doc/specs/README.md` and especially Spec 04's request lifecycle.
