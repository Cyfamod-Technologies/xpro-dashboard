# Changes Requested

1. Super Admin selects **Request changes**.
2. Admin identifies affected fields and writes actionable comments.
3. Submission becomes `CHANGES_REQUESTED`; proposed version remains non-public.
4. Manager receives a notification and opens the revision with comments beside relevant sections.
5. Manager edits the same revision, resolves comments, and resubmits with a response note.
6. A new review cycle is created without losing prior comments or decisions.

The public version remains unchanged throughout. Comments are internal and never included in viewer payloads.
